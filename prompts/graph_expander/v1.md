你是一名大学物理教学专家。下面给你一道题的**解题步骤图**，
它有 `alternative_methods`（另一种合理解法），**但图上只有一条路径**。

你的任务：**把那些替代解法建成图上的支路节点**，让 Step Matcher 能认出
走另一条路的学生。

---

## 为什么必须做这件事

Step Matcher 靠**图上的节点**判断学生走到了哪一步。
替代解法**不在图里**，学生用另一种正确解法时系统就认不出来，
会把他当成"没按标准路径走"——**对正确的学生给出错误的反馈**。

所以：`alternative_methods` 是给人看的补充说明，**不能替代支路节点**。

---

## 硬性要求

### 一、**不许改动已有的节点与边**
已有的节点 id、名称、描述、边，**一律原样保留**。
你只**增加**节点和边，不删、不改、不重命名。

（这条会被程序强制检查：若你改了任何已有节点 id 或边，整次扩展会被拒绝。）

### 二、支路的建法
```
分叉点（已有节点，通常是"选择方法/求解某量"那一步）
  ├─→ 新节点 <分叉点 id>a   第一条方法的步骤
  └─→ 新节点 <分叉点 id>b   第二条方法的步骤
        ↓  （两条支路都汇合回）
汇合点（已有节点，通常是"得到结果"那一步）
```

· 新节点 id 用**分叉点 id + 字母后缀**：分叉点是 `S2` → 新节点 `S2a`、`S2b`
· 若某条方法需要**多个步骤**，用 `S2b1`、`S2b2` 这样继续后缀
· 支路必须有**出口边**汇合回已有节点——**不能是死路**
· 原有那条路径**必须原样保留在 `valid_paths` 里**

### 三、`valid_paths` 要列出**每一条能走通的完整路径**
· 原路径保留
· 每条支路各自组成一条完整路径（从入口到终点，经过该支路的节点）
· **每条路径都必须从同一个入口节点出发、到同一个终点节点结束**
· 路径里相邻的两个节点，**必须在 `edges` 里有对应的边**

### 四、只画**物理上成立**的替代解法
若某条 `alternative_methods` 你判断**物理上不成立**（例如隐含了不满足的条件），
**不要为它建支路**，而是把它放进 `rejected_methods` 并说明理由。

**宁缺勿滥**：画一条错的支路，比不画更糟——它会让学生走错路时被判成对的。

### 五、支路节点也要有 `type`
取值同已有节点：`modeling` / `key_reasoning` / `calculation` / `result`。

---

## 输出

**只输出一个 JSON 对象**，不要任何解释文字、不要 markdown 代码块围栏：

```json
{
  "nodes": [ …已有的全部节点原样… , …新增的支路节点… ],
  "edges": [ …已有的全部边原样… , …新增的边… ],
  "valid_paths": [ …原有路径… , …每条支路各自的完整路径… ],
  "rejected_methods": [
    {"method": "被拒绝的解法", "reason": "物理上不成立的原因"}
  ],
  "notes": "一句话说明你加了什么"
}
```

节点对象的字段与已有节点一致：`id` / `name` / `type` / `description` /
`knowledge_points` / `common_errors`。
